# 절차 엔진 MCP 서버 (프로토타입)

검증된 절차를 **정해진 순서대로, 한 단계씩** 실행하는 MCP 서버입니다.
중요한 단계는 **사람이 승인해야** 실행되고, 진행 상황은 **절차 매트릭스**로 보여줍니다.

```
사용자 ──말로 요청──▶ AI (Claude 등)
                        │  MCP 도구: start_procedure → run_next_step → wait_for_approval …
                        ▼
                   절차 엔진 ── 순서 강제 · 단계별 검증 · 실행 기록
                        │
          승인 단계 ────┼──▶ 승인자에게 링크 발송 (AI는 링크를 받지 못함)
                        │        └ 승인자가 /approve/<token> 에서 승인·거절
                        ▼
                   Playwright로 웹 화면 조작 (단계마다 스크린샷)
```

## 핵심 규칙

| 규칙 | 구현 |
|---|---|
| 순서대로만 실행 | `run_next_step`은 다음 단계 하나만 실행합니다. 건너뛰기 도구는 없습니다. |
| 승인은 사람만 | AI 도구에 승인 기능이 없습니다. 승인 링크는 승인자에게만 가고, 기록 파일에는 토큰 해시만 남습니다. |
| 승인 주체 구분 | 단계마다 `회원`, `관리자` 등 승인 주체가 정해져 있고, 해당 주체에게만 요청이 갑니다. |
| 실행 후 확인 | 각 단계는 실행 후 화면을 확인하고 근거를 남깁니다. 확인에 실패하면 절차가 멈춥니다. |
| 기록 | 단계별 상태·근거·스크린샷·승인 내역이 실행 기록(JSON)과 대시보드에 남습니다. |

## 사용법 1: 내 컴퓨터에서 시험하기 (알림톡 없이)

준비물: Python 3.10 이상, Node.js 18 이상, [Claude Code](https://code.claude.com)

**① 설치 (처음 한 번)**

```bash
git clone https://github.com/soonong/eeff.git && cd eeff
pip install -r procedure_mcp/requirements.txt
playwright install chromium
```

**② 서버 켜기** (터미널 창 하나를 서버용으로 열어 두세요)

```bash
python -m procedure_mcp
```

```
절차 엔진 MCP 서버
  MCP 주소      http://127.0.0.1:8765/mcp
  대시보드      http://127.0.0.1:8765/dashboard?key=...
  승인 알림     콘솔 (이 창과 var/procedure_runs/outbox.log)
```

**③ Claude Code에 연결 (처음 한 번)** 다른 터미널 창에서:

```bash
claude mcp add --transport http procedure http://127.0.0.1:8765/mcp
```

**④ Claude에게 시키기** 같은 창에서 `claude`를 실행하고:

> 회원정보 업종 추가 절차로 토목공사업 추가해줘

Claude가 절차 카드를 보여주고 한 단계씩 진행하다가, 승인 단계에서 멈추고 "회원에게 승인 요청을 보냈다"고 알려줍니다.

**⑤ 승인하기** 서버 창에 승인 링크가 뜹니다. 이 창이 승인자의 휴대폰 역할입니다.

```
📨 [회원에게 발송] 승인 요청: 회원정보 변경 - 등록 업종 추가 / 업종 추가 입력 (실행 20261115-b6f17e) → http://127.0.0.1:8765/approve/...
```

링크를 브라우저로 열어 절차 카드, 직전 단계 화면, 절차 매트릭스를 보고 **승인** 또는 **거절**을 누릅니다.
Claude는 승인을 기다리고 있다가 이어서 진행합니다. 5단계 저장은 **관리자** 승인이라서 링크가 한 번 더 뜹니다.

진행 상황은 대시보드 주소로도 볼 수 있습니다.

## 사용법 2: 카카오 알림톡으로 승인 받기

승인 링크를 승인자 휴대폰으로 **카카오 알림톡**으로 보냅니다. 발송은 [SOLAPI(솔라피)](https://solapi.com)를 거칩니다.

### 미리 준비할 것

| 준비물 | 어디서 | 설정값 |
|---|---|---|
| 카카오톡 채널 (비즈니스 채널) | 카카오톡 채널 관리자센터 | |
| SOLAPI 가입, API 키 발급 | SOLAPI 콘솔 | `SOLAPI_API_KEY`, `SOLAPI_API_SECRET` |
| 채널을 SOLAPI에 연결 (발신 프로필) | SOLAPI 콘솔 → 카카오 채널 연동 | `KAKAO_PF_ID` (KA01PF로 시작) |
| 알림톡 템플릿 등록과 카카오 검수 | SOLAPI 콘솔 → 알림톡 템플릿 (아래 문구 사용) | `KAKAO_TEMPLATE_ID` (KA01TP로 시작) |
| 승인 페이지 공개 주소 (https) | 서버 배포 또는 고정 터널 | `PROCEDURE_PUBLIC_URL` |
| 승인자 휴대폰 번호 | | `PROCEDURE_APPROVER_PHONES` |
| (선택) 문자 대체발송용 발신번호 | SOLAPI 콘솔 → 발신번호 등록 | `SMS_SENDER_NUMBER` |

**공개 주소가 필요한 이유:** 승인자는 휴대폰에서 알림톡 버튼을 눌러 승인 페이지를 엽니다. 그래서 `127.0.0.1`이 아닌 인터넷에서 열리는 **https 주소**가 필요합니다.
템플릿 버튼에 도메인을 고정해서 등록하기 때문에 **주소가 바뀌지 않아야** 합니다. 매번 바뀌는 임시 터널 주소는 쓸 수 없습니다.

### 알림톡 템플릿 (검수 신청할 문구)

메시지 유형은 **기본형**, 분류는 **정보성 메시지**입니다.

```
[승인 요청]
#{승인주체}님, 아래 작업의 승인이 필요합니다.

■ 절차: #{절차명}
■ 단계: #{단계명}
■ 실행 번호: #{실행번호}
■ 승인 기한: #{승인기한}

버튼을 눌러 내용을 확인한 뒤 승인 또는 거절해 주세요.
본인이 요청하지 않은 작업이면 거절해 주세요.
```

버튼: **웹링크**, 버튼 이름 `승인 화면 열기`, 모바일/PC 링크 모두 `https://<공개 도메인>/approve/#{승인토큰}`

변수 6개(`승인주체`, `절차명`, `단계명`, `실행번호`, `승인기한`, `승인토큰`)를 서버가 채워서 보냅니다.
템플릿 문구를 바꾸면 `notifier.py`의 `KakaoAlimtalkNotifier.variables()`도 같이 맞춰야 합니다.

> **확인 필요:** 버튼 링크에 변수를 쓰는 방식(도메인 고정 + 경로에 변수)은 검수 단계에서 꼭 확인하세요.
> 이 구현을 만든 환경에서는 SOLAPI·카카오 문서 사이트에 접속할 수 없어서, 발송 형식은 SOLAPI 공식 Python SDK(5.0.3) 소스로 확인했고 버튼 변수 정책은 확인하지 못했습니다.
> 검수에서 거절되면 `#{승인토큰}` 대신 다른 형태(예: 본문에 링크)로 템플릿을 바꾸고 `variables()`를 맞추면 됩니다.

### 설정하고 켜기

저장소 루트의 `.env` 파일에 적습니다. `.env`는 git에 올라가지 않습니다.

```bash
SOLAPI_API_KEY=발급받은_키
SOLAPI_API_SECRET=발급받은_시크릿
KAKAO_PF_ID=KA01PF...
KAKAO_TEMPLATE_ID=KA01TP...
PROCEDURE_PUBLIC_URL=https://approve.내도메인.com
PROCEDURE_APPROVER_PHONES=회원=01012345678;관리자=01098765432,01011112222
SMS_SENDER_NUMBER=0212345678        # 선택: 알림톡 실패 시 문자로 대신 보냄
```

```bash
python -m procedure_mcp
#   승인 알림     카카오 알림톡 (회원 1명, 관리자 2명, 문자 대체발송 켜짐)
```

`SOLAPI_API_KEY`가 있으면 자동으로 알림톡을 씁니다. 콘솔로 되돌리려면 `PROCEDURE_NOTIFIER=console`로 설정하세요.

**알림톡을 쓸 때의 동작**

- 승인 링크는 **알림톡으로만** 갑니다. 콘솔과 `outbox.log`에는 "알림톡 발송 (1/1건 접수)"만 남고 링크는 남지 않습니다.
- 발송에 실패하면(번호 없음, 템플릿 불일치, 키 오류 등) 단계는 실행되지 않습니다. Claude가 실패 이유를 알려주고, 원인을 해결한 뒤 다시 진행하면 새 링크로 다시 보냅니다.
- 승인 주체의 번호가 여러 개면 모두에게 보내고, 그중 한 명이 먼저 승인하거나 거절하면 그 결정으로 처리됩니다.
- 공개 주소로 열 수 있는 것은 승인 페이지와 대시보드뿐입니다. MCP 주소(`/mcp`)는 서버를 `127.0.0.1`로 켜 두면 공개 주소로 접속해도 거부됩니다(421).
- 지금은 역할별로 번호를 고정합니다. 실서비스에서 "회원"은 절차를 요청한 그 회원이어야 하므로, 회원 DB에서 번호를 찾도록 바꿔야 합니다.

## MCP 도구

| 도구 | 하는 일 |
|---|---|
| `list_procedures` | 절차 목록과 절차 카드(버전, 검수 정보, 단계, 승인 주체) |
| `start_procedure` | 실행을 만들고 절차 카드를 돌려줌 (아직 아무것도 실행 안 함) |
| `run_next_step` | 다음 단계 하나 실행. 승인 단계면 실행하지 않고 승인 요청 발송 |
| `wait_for_approval` | 승인자의 결정을 최대 120초 기다림 |
| `get_run_status` | 실행 하나의 절차 매트릭스와 최근 기록 |
| `list_runs` | 최근 실행 전체 현황 (실행 × 단계) |
| `cancel_run` | 실행 취소 (기다리던 승인 요청도 무효) |

## 새 절차 추가하기

1. **단계 동작 만들기**: `actions/<이름>.py`에 `async def 단계(ctx) -> str` 함수를 만듭니다.
   실행만 하지 말고 결과를 확인하고, 실패하면 예외를 던집니다.
   `playwright codegen <사이트 주소>`로 녹화한 코드를 단계별로 나눠 넣으면 빠릅니다.
2. **등록**: `actions/__init__.py`의 `ACTIONS`에 합칩니다.
3. **절차 정의**: `procedures/<이름>.yaml`에 단계 순서, 승인 주체, 검증 정보를 적습니다.
   예시는 [`procedures/member_upjong_add.yaml`](procedures/member_upjong_add.yaml)입니다.

서버를 시작할 때 정의 파일이 참조하는 동작이 모두 있는지 검사합니다.

## 설정 (환경변수)

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PROCEDURE_HOST` / `PROCEDURE_PORT` | `127.0.0.1` / `8765` | 서버 주소 |
| `PROCEDURE_PUBLIC_URL` | `http://<host>:<port>` | 승인 링크에 쓰는 바깥 주소 |
| `PROCEDURE_DATA_DIR` | `var/procedure_runs` | 실행 기록, 스크린샷, outbox |
| `PROCEDURE_ADMIN_KEY` | 실행마다 새로 생성 | 대시보드 키 |
| `PROCEDURE_HEADLESS` | `1` | `0`이면 브라우저 창을 띄워서 보면서 실행 |
| `PLAYWRIGHT_CHROMIUM_EXECUTABLE` | 없음 | 미리 설치된 Chromium 경로 |
| `PROCEDURE_DEMO_USER` / `PROCEDURE_DEMO_PASSWORD` | `demo` | 데모 사이트 로그인 값 |
| `PROCEDURE_NOTIFIER` | `SOLAPI_API_KEY`가 있으면 `kakao`, 없으면 `console` | 승인 알림 방식 |
| `SOLAPI_API_KEY` / `SOLAPI_API_SECRET` | 없음 | SOLAPI API 키 |
| `KAKAO_PF_ID` / `KAKAO_TEMPLATE_ID` | 없음 | 카카오 채널(발신 프로필) ID, 알림톡 템플릿 ID |
| `PROCEDURE_APPROVER_PHONES` | 없음 | 승인 주체별 번호. `회원=010...;관리자=010...,010...` |
| `SMS_SENDER_NUMBER` | 없음 | 등록된 발신번호. 있으면 알림톡 실패 시 문자로 대체발송 |
| `SOLAPI_BASE_URL` | `https://api.solapi.com` | 테스트용으로만 바꿈 |

## 프로토타입의 한계 (실서비스 전에 할 일)

- **MCP 주소에 인증이 없습니다.** 서버를 `127.0.0.1`로 켜 두면 내 컴퓨터에서만 MCP에 접속됩니다. 다른 곳에서 AI가 접속하게 하려면 OAuth 등 인증을 붙여야 합니다.
- **실제 알림톡 발송은 아직 시험하지 못했습니다.** 가짜 SOLAPI 서버로 요청 형식과 전체 흐름은 확인했지만, 실제 키·채널·검수된 템플릿으로 한 번 보내 봐야 합니다.
- **콘솔 모드에서는 승인 링크가 `outbox.log`에 남습니다.** Claude Code처럼 AI가 내 컴퓨터 파일을 읽을 수 있는 환경에서는 시험용으로만 쓰세요. 실제 승인 경로는 알림톡처럼 AI 밖이어야 합니다.
- **승인 페이지의 본인 확인이 링크 토큰뿐입니다.** 알림톡이 승인자 본인 휴대폰으로 가는 것이 1차 확인입니다. 실서비스에서는 승인자 로그인이나 본인인증을 함께 요구하세요.
- **서버를 재시작하면 브라우저 세션이 사라집니다.** 실행 중이던 단계는 실패로 정리되고, 승인 대기 중이던 실행은 다음 단계의 화면 확인에서 걸러집니다.
- **claude.ai 웹/앱의 커스텀 커넥터로 쓰려면** 공개 HTTPS 주소에 배포해야 합니다.
